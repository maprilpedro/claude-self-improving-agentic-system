# Claude Projects as Queryable Exec Artifacts

_Section: Cross-Org Influence Without Authority — part of `leadership/`; router = README.md._
- **Date identified**: 2026-04-21
- **Source**: Jaclyn Eckersley (Director Eng Program Mgmt, reports to VP Alexander Saar) during P42 Status meeting, April 21. Pedro + Yanira + Jaclyn discussing how to prep Loni + Jean-Michel for the week-of-May-4 presentation. Jaclyn: "I've done quite a lot of stuff and give him Claude projects and AI where he can just query it himself. So a lot of the teams have got their analysis done from AI — just create a project and put it in there and then they can do it themselves. That's kind of what I've done with some of the stuff I've given to him… I've just done it for the AEM survey. It's mind blowing."
- **Pattern**: The old model is "write a 10-slide summary, deliver it in a 30-minute meeting, hope the VP absorbs the key facts." The Claude-project model is "load the full analysis into a Claude project, hand the VP the link, let them interrogate it themselves at their own pace." This flips three things at once: (1) the VP gets deeper answers than any summary could give, on their own schedule; (2) the analysis stays consistent — there's no telephone-game distortion between what the PM built and what the VP walks away with; (3) the PM's work becomes re-queryable infrastructure, not a one-shot artifact that decays after the meeting. VPs are increasingly AI-fluent — handing them a Claude project is both a deliverable AND a demonstration that you operate at the AI-native level.
- **Why this is a Senior Director move**: Directors optimize the meeting. Senior Directors optimize the decision-making that happens between meetings. A Claude project is a between-meetings asset. It outlives the review. It also signals that you've already internalized the AI-native exec workflow — which is itself a visibility multiplier when your VPs are thinking about AI adoption at company level.
- **How to apply**: For any high-stakes exec artifact (agent report rollup, Summit survey, state-of-strategy), build the analysis in a Claude project rather than only a deck. Share the project link alongside the deck. Include: the raw data, the method notes, the key charts as artifacts, and a curated set of example queries the exec can start from. Treat the deck as the summary; the project as the system-of-record.
- **Anti-pattern**: Loading unstructured raw data into a project without curation. The VP bounces off. Invest 30 minutes to seed 5-10 example queries with high-quality answers already computed. That's what makes it "mind blowing" vs. "another link I won't open."
