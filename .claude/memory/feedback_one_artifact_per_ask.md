When Pedro asks for one document, the ask IS the artifact. Don't create supporting files unless explicitly asked.

**Why:** April 30, 2026 session — Pedro asked for a report audit. I created the audit, then drafted a "May 4 slide" file when offered (Pedro picked option b), then created a "v0 outline spec" file when discussing the new Portfolio Briefing. End state: 3 new vault files for what should have been 1. Pedro's response: *"how many files do you have? I want the audit to be the main one — others shall not exist."* He deleted the two extras.

**How to apply:**

- When Pedro picks an option from a menu (a/b/c), default to *adding to the existing artifact* not creating a new one.
- When the conversation expands a topic (e.g., from audit findings → slide implications → portfolio briefing), keep adding to the original file as new sections rather than spawning new files.
- Spec docs / slide drafts / distribution plans are valid in some contexts, but they should be sections within the canonical artifact unless Pedro explicitly asks for separate files.
- Before creating a new vault file, ask: *can this be a new section in the existing one?* If yes, add a section.
- This is a special case of the "too much info" feedback — file proliferation is the structural form of information overload.
