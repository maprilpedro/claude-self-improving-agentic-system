**Rule.** When Bertrand owns an item — relationship repair within his org, workstream he took ("Je vais m'occuper de…"), executive smoothing, agenda design — DO NOT add it to Pedro's Status & Todo. Stakeholder Map entry for context only is fine.

**Why:** Pedro's plate is finite. Tracking Bertrand-owned items as Pedro tasks creates false ownership and noise on the focus list. Bertrand handles repair within his own scope of relationships better than Pedro can — Pedro intervening would be overstep.

**How to apply:**
- If Pedro creates friction with someone in Bertrand's org (Cédric Huesler May 5 = example), capture in Stakeholder Map as context, NOT as a "smooth/repair" task.
- If Bertrand says *"Je vais m'occuper de X"* (e.g., MCP workstream May 5), close any existing Pedro task for X. Add a note that ownership transferred.
- Pedro's tracker = items where action is on Pedro or someone Pedro coordinates. NOT items where action is on Bertrand.
- Memory and State of Project notes can mention the friction or context — those aren't tasks.

Pedro corrected: *"Cedric Repair is on Bertrand, dont trace it."* Removed task. Stakeholder Map entry rewritten to "Repair = Bertrand's call, not Pedro tracked. Note for context only."
